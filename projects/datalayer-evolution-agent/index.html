DataLayer Evolution Agent

LLM growth intelligence, live in production

A production system that turns DataLayer's product, marketing, and lead data into one prioritized growth brief, emailed to the team every morning.

  • Live in production
  • 4 data sources
  • 10 bugs caught pre-launch
  • Built in 3 phases
Live product ↗Repository ↗

The problem

Growth decisions at DataLayer relied on manually checking product, marketing, and lead data across scattered sources.

What I built

  • A daily batch job that pulls data from the internal database, GA4, Search Console, and Reddit, then synthesizes it with an LLM into one prioritized “Growth Brief”.
  • A deliberately minimal, production-safe stack (Flask, PostgreSQL, APScheduler, Docker). Heavier frameworks such as LangChain, vector databases, Celery, and Kubernetes were left out to keep the system auditable and easy to reason about.
  • Least-privilege data access with separately scoped read-only and write database roles, so a bug in the write path can never compromise the read-only analysis.
  • Graceful degradation across sources: a failed source is logged and surfaced instead of crashing the pipeline.
  • LLM reliability by moving judgment into code: metrics are precomputed and passed as exact figures, outputs are re-sorted deterministically, and an anti-overclaiming design stops the model from claiming false causation on low-traffic data.
  • An extension that finds leads and drafts customized outreach emails for each prospect, with every message reviewed before it is sent.

Results

  • Running daily in production against real company data.
  • Found and fixed a real data-integrity bug where internal test accounts were counted as paying customers.
  • Delivered in three phases over one month, followed by a structured 8-angle code review that surfaced and fixed 10 bugs before production.
