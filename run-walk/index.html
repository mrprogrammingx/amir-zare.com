Run/Walk Data Pipeline

Batch telemetry pipeline: CSV → Parquet → DuckDB

An end-to-end batch pipeline that turns raw activity CSV files into fast, analytics-ready DuckDB tables, orchestrated by Apache Airflow and served through a Streamlit dashboard and a JSON API.

  • Sub-second analytical queries
  • Airflow-orchestrated
  • Parquet data lake

Key features

Incremental ingestion

Batch ingestion with idempotent transforms, so re-runs are safe.

Validation

Row-level validation and schema checks catch bad data early.

Columnar storage

Raw CSV converted to compressed Parquet for smaller, faster reads.

Materialized tables

DuckDB summary tables answer analytical queries in under a second.

Dashboards & API

A Streamlit dashboard and lightweight JSON endpoints for ad-hoc reporting.

Tested

Pytest and CI-oriented sample dataset generation.

The problem

CSV telemetry ingestion was slow and hard to query, blocking analytics.

What I built

  • Airflow DAGs that orchestrate dataset download, ingestion, and transformation stages.
  • Ingestion that converts raw CSV activity datasets into optimized Parquet files inside a local data lake.
  • SQL transformations that materialize summary tables in DuckDB: daily_user_summary, daily_activity_counts, and daily_wrist_counts.
  • Interactive Streamlit dashboards for activity trends and user behavior, plus REST-style JSON endpoints in Flask.
  • A Docker Compose development environment that includes the Airflow services.

Results

  • Daily materialized reports that analysts can query in seconds instead of waiting for slow CSV loads.
  • Smaller storage and less I/O by moving from raw CSV to compressed Parquet.
  • Manual reporting replaced by automated dashboards and APIs.
