FlowFleet

Real-time logistics data platform

A production-style real-time streaming platform for a fictional delivery company: change data capture from PostgreSQL into Kafka and Flink, deployed on Kubernetes and load-tested to 50,000 events per second.

  • Load-tested to 50k events/sec
  • p50/p95/p99 latency tracked
  • 8 phases with tests and notes
Repository ↗

The problem

A delivery company needs live driver locations, geofencing, and analytics from operational data, without losing or duplicating events when things fail.

What I built

  • Change data capture from PostgreSQL/PostGIS with Debezium, covering snapshot versus streaming modes, tombstones, and replication slot and connector recovery.
  • Kafka topics with Avro and Schema Registry, a high-volume driver-location simulator, and consumer-group rebalancing tests.
  • Apache Flink jobs in Java 21 using keyed state, event-time windows, watermarks, timers, and side outputs, including broadcast-state geofencing with JTS.
  • Sinks to TimescaleDB and ClickHouse with batching, retries, and idempotent writes, plus BigQuery for analytics.
  • Failure handling: a dead-letter queue for poison messages, late-data handling, checkpoint and savepoint recovery, and backpressure experiments.
  • Deployment on Kubernetes with Helm, the Flink Kubernetes Operator (savepoint-based upgrades), and Argo CD (app-of-apps GitOps).

Results

  • Load-tested from 1k to 50k events per second with a live-adjustable rate generator and end-to-end p50/p95/p99 latency histograms.
  • Tuned throughput and added the Flink autoscaler and a consumer HPA.
  • Prometheus and Grafana observability across the whole pipeline.
