# amir-zare.com — Personal site

This repository contains the static website for amir-zare.com. It's a plain HTML/CSS/JS site (no build step).

Pages included:
- `index.html` — homepage (sections are hand-edited; header, footer and SEO tags are generated)
- `about/`, `projects/` (hub + one page per project), `community/` — generated by `tools/build.py`
- `resume.html` — printable résumé page (the body is generated from the Word master resume, see below)
- `analytics/`, `run-walk/`, `classic-web-based-online-chat-application/` — hand-written case studies
- `kb.json` — the resume as standalone third-person facts, read by the "Ask about Amir" Hugging Face Space

## 🤖 Ask about Amir

An AI assistant on [amir-zare.com](https://amir-zare.com/#ask) that answers questions about my experience using only facts from my resume, with a checked citation for every sentence.

- Retrieval runs in the browser (all-MiniLM-L6-v2 via Transformers.js)
- Answers come from Llama 3.3 70B on Cloudflare Workers AI ([`ask-worker/`](ask-worker/))
- Personal questions are refused by rule; $0/month on free tiers

[Try it](https://amir-zare.com/#ask) · [How it works](https://amir-zare.com/projects/ask-about-amir/) · [Hugging Face Space](https://huggingface.co/spaces/amirzaredev/ask-about-amir)

## Updating the resume (the Word master is the source of truth)

Edit facts only in the Word master resume, then:

```bash
python3 tools/import_resume.py "/path/to/Master Resume.docx"   # writes tools/resume_data.json
python3 tools/build.py                                         # updates resume.html, llms.txt, the About FAQ, kb.json
node tools/make-pdf.mjs                                        # prints Amir_Zare_Resume.pdf (max 3 pages) and Amir_Zare_Resume_Full.pdf
git add -A && git commit -m "Resume: <what changed>" && git push
```

- The two PDFs behind the "Download resume" / "Download full resume" buttons come from the same page:
  `resume.html?version=short` and `resume.html?version=full`. `make-pdf.mjs` needs Google Chrome (set `CHROME=` for
  another path). Text is fixed at 10pt minimum; if the short PDF is over 3 pages it fails and says by how much, so trim the
  master. The short-version limits are `SHORT_RESUME` in `tools/content.py`.
- The short version shows the summary paragraph, the first bullets of each job (per-job limits), only projects marked
  with a ★ at the start of their title in the master (2 bullets + Tech line; if none are marked: DataLayer Evolution
  Agent, FlowFleet, AI Phone Assistant, Cookie Cats A/B Test), skills as one line per category, the 5 most recent
  certifications, and Teaching & Community as one line; no Interests, Hackathons or training details. All limits are
  `SHORT_RESUME` in `tools/content.py`.
- `build.py --check` fails if `tools/resume_data.json` changed since the PDFs were printed (`tools/resume-pdf.json` keeps
  the hash), so CI catches PDFs that weren't regenerated.

- The `.docx` is never committed (`*.docx` is in `.gitignore`): it holds the phone number and personal email.
  The importer drops those, credential IDs and street addresses, and both the importer and the build refuse to
  continue if `tools/resume_data.json` contains a phone number, a personal email or a credential ID.
- `tools/resume_data.json` is committed, so CI builds without the `.docx`.
- The importer follows the master's structure (Heading 1 sections, Heading 4 project groups, bold titles ending in a
  date, bullets). If it doesn't recognize something it stops and names the section and paragraph instead of skipping it.
- The resume shows each project's first bullet; `kb.json` has every bullet. Hand-written pages (Home sections, About,
  Community, translations) are not rewritten automatically: update them when a fact there changes.

Build step (Python 3.12+, standard library only):

```bash
python3 tools/build.py          # regenerate pages, shared header/footer, sitemap.xml, robots.txt, llms.txt, kb.json
python3 tools/build.py --check  # CI: fails if generated files (including resume.html, llms.txt, kb.json) are out of date
```

Content for generated pages lives in `tools/content.py`. The header and footer are defined once in `tools/build.py`
and synced into every page. Share images (`images/og/*.jpg`) are rendered with headless Chrome:

```bash
python3 -m http.server 8000 &
node tools/make-og.mjs http://localhost:8000
```

Local preview:

```bash
# from the project folder
python3 -m http.server 8000
# open http://localhost:8000 in your browser
```

Deployment:

The site is intended to be hosted on GitHub Pages for `amir-zare.com` (CNAME present).

After editing the homepage sections or styles, run `python3 tools/build.py` so the shared parts stay in sync.
