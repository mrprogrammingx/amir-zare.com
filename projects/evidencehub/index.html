EvidenceHub

MySQL performance and sharding, backed by benchmarks

A reference data platform that migrates a deliberately poor legacy MySQL schema to an optimized, sharded design, where every performance claim is backed by a measured benchmark.

  • p95 < 50 ms SLOs
  • 4-shard MySQL 8
  • 20M-row dataset
Repository ↗

The problem

Performance work is often based on assumptions; this project proves every improvement with numbers.

What I built

  • A 4-shard MySQL 8 cluster with a catalog database and Redis in Docker Compose, plus a synthetic data generator that scales to 20M rows.
  • 8 mission-critical queries, each with a latency SLO (p95 under 50 ms for point and latest-N lookups), and a Locust + EXPLAIN ANALYZE benchmark harness that produced the baseline report.
  • Strict engineering standards: mypy --strict, Ruff, Pytest/Hypothesis, GitHub Actions CI with full-history secret scanning, and architecture decision records.

Results

  • Roadmap: online schema migration, shard routing and resharding, Kafka ingestion with a DLQ, a Redis-cached FastAPI layer, and a Spark/Iceberg warehouse orchestrated by Airflow.
